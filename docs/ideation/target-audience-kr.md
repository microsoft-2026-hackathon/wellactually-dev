# wellactually의 타깃과 핵심 문제

기준일: 2026-09-11

상태: 타깃 정의와 제품 방향에 대한 논의 정리. 시장 규모와 효과는 검증 전 가설입니다.

## 1. 한 문장 정의

**코딩 에이전트로 실제 개발과 배포는 할 수 있지만, 숙련된 개발자의 판단 과정을 경험하고 자신의 역량으로 형성할 기회가 부족한 Coding Agent Native 주니어 엔지니어.**

wellactually는 이 사람이 실제 업무를 진행하면서 엔지니어링 판단과 에이전트에게 일을 맡기는 능력을 함께 기르도록 돕는 페어 프로그래밍 서비스입니다.

## 2. 출발점이 된 실제 사용자

제품을 구상한 사용자는 CSP 회사의 1년 차 엔지니어입니다.
개발 경력을 시작할 때부터 코딩 에이전트가 있었으며, 코딩 에이전트 이전 방식으로 개발한 경험은 없습니다.
에이전트 활용이나 배포 프로세스에는 익숙하지만, 숙련된 개발자가 개발 작업을 진행할 때의 고려 사항과 설계 과정을 경험하기 어렵다는 문제를 느끼고 있습니다.

이 경험은 초기 타깃을 구체화하는 출발점입니다.
다만 CSP 재직 여부나 정확히 1년 차라는 조건이 제품의 필수 사용 자격은 아닙니다.
핵심은 연차나 회사 유형보다 **에이전트 중심의 개발 경험과 엔지니어링 판단을 형성할 기회 사이의 간극**입니다.

## 3. Coding Agent Native란

이 문서에서는 개발 경력을 시작할 때부터 코딩 에이전트를 일상적인 작업 수단으로 사용해 온 사람을 뜻합니다.
나이, 특정 모델 사용 여부, 직접 코딩 능력을 기준으로 분류하는 표현은 아닙니다.

이 타깃은 다음과 같은 일을 할 수 있습니다.

- 에이전트에게 구현 작업을 요청하고 결과물을 얻습니다.
- 도구와 서비스를 연결해 작동하는 기능을 만듭니다.
- 개발 환경과 배포 프로세스를 활용해 결과물을 전달합니다.

하지만 결과물을 만드는 능력과 아래의 판단을 스스로 수행하는 경험은 같지 않습니다.

- 해결해야 할 문제와 요청된 해결책을 구분하기
- 요구사항의 빠진 전제와 제약을 발견하기
- 문제를 작게 나누고 작업 순서를 정하기
- 설계 대안과 트레이드오프를 비교하기
- 불확실한 부분에 대해 가설을 세우고 확인 방법을 고르기
- 변경의 영향 범위, 복잡성, 유지보수 비용을 판단하기
- 완료 기준을 정하고 결과가 그 기준을 충족하는지 확인하기

모든 Coding Agent Native 개발자가 이러한 경험이 부족하다고 단정하지 않습니다.
이 중 실제로 공백을 느끼고, 업무 과정에서 이를 채우려는 사람이 초기 핵심 타깃입니다.

## 4. 핵심 Pain Point: 판단 역량을 형성할 기회의 공백

문제는 단순히 “코드를 못 쓴다”거나 “에이전트를 사용할 줄 모른다”가 아닙니다.

**구현 결과는 얻지만, 그 결과에 이르는 중요한 판단을 경험하거나 숙련된 동료 옆에서 관찰할 기회가 부족하다는 것**입니다.
작업 분해, 설계 선택, 검증 방법 결정 등이 에이전트의 작업 안에서 처리되면 사람은 요청과 결과만 보게 될 수 있습니다.

이는 기존 개발자가 이미 갖고 있던 역량을 덜 사용하면서 겪는 문제와 구분됩니다.
이번 타깃의 중심 문제는 역량의 퇴화보다 **처음부터 그 역량을 형성할 경험이 충분히 주어지지 않는 것**에 가깝습니다.

또한 아직 경험하지 못한 판단 과정에 대해서는 무엇을 질문해야 할지도 알기 어렵습니다.
따라서 사람이 먼저 질문해야만 작동하는 설명 도구만으로는 핵심 문제를 해결하기 어렵습니다.

## 5. 배우고 싶은 것은 과거의 수작업이 아니라 판단 과정

“캐시를 추가해줘”라는 요청을 구현하고 배포하는 것과, 캐시를 도입해야 하는지 판단하는 것은 다릅니다.
숙련된 페어는 다음과 같은 질문을 드러낼 수 있습니다.

> 캐시가 필요한 병목인지 먼저 확인했어?
>
> 이 데이터는 얼마나 오래된 값까지 허용돼?
>
> 캐시 무효화가 실패하면 어떤 문제가 생겨?
>
> 복잡성을 추가하는 비용보다 효과가 큰가?

여기서 중요한 학습은 질문 목록을 외우는 것이 아닙니다.

- 왜 지금 이 질문을 해야 하는지 이해합니다.
- 무엇을 관찰하면 판단할 수 있는지 배웁니다.
- 자신의 작업 맥락을 바탕으로 대안을 선택합니다.
- 그 선택이 구현과 운영 결과에 어떻게 연결되는지 확인합니다.

이 판단은 코딩 에이전트 이전 시대에만 유효한 기술이 아닙니다.
에이전트에게 일을 맡기는 현재에도 필요합니다.
목표는 예전의 개발 방식으로 되돌아가는 것이 아니라, 그 과정에서 길러졌던 판단 역량을 현재의 작업 방식 안에서 형성하는 것입니다.

## 6. 함께 기르려는 두 가지 역량

### 엔지니어링 판단 능력

문제 정의, 요구사항 구체화, 설계 비교, 탐색과 디버깅, 영향 범위 판단, 검증 기준 설정을 실제 작업에서 연습합니다.
“시니어의 정답”을 받아들이는 것이 아니라, 선택의 근거와 조건을 이해하고 자신의 판단을 내리는 것이 목표입니다.

### 코딩 에이전트에게 일을 맡기는 능력

에이전트를 사용하는 데 익숙한 것과 일을 잘 맡기는 것은 별개입니다.
무엇을 맡길지, 어디까지 맡길지, 어떤 제약을 줄지, 언제 결과를 확인할지 결정하는 능력도 필요합니다.

- 목표와 기대 결과를 명확히 표현합니다.
- 한 번에 맡길 작업 단위와 범위를 정합니다.
- 변경하면 안 되는 부분과 확인해야 할 조건을 전달합니다.
- 모호한 부분을 에이전트가 임의로 결정하지 않도록 합니다.
- 결과를 보고 다음 지시를 조정합니다.

따라서 Coach가 지시문을 완성해 Driver에게 전달하는 편의가 항상 이 타깃에게 이득인 것은 아닙니다.
사람이 판단을 자신의 말로 지시하고, 그 지시의 결과를 경험하는 과정도 학습의 일부입니다.

## 7. 이 타깃을 기준으로 한 현재 제품 방향

기본 패턴은 **AI Driver–Human Navigator–AI Coach**입니다.

### 사람

중요한 판단을 하고, 그 판단을 바탕으로 Driver에게 직접 일을 맡깁니다.
Coach의 제안을 거절하거나 보류할 수 있어야 합니다.

### Driver

사람이 전달한 목표와 제약에 따라 구현합니다.
이 제품은 사람이 모든 코드를 직접 타이핑해야 한다고 전제하지 않습니다.

### Coach

사람이 아직 질문하지 않은 중요한 판단 지점을 먼저 드러냅니다.
상위 설계뿐 아니라 실제 구현과 연결되는 구체적인 질문, 근거, 대안을 제공할 수 있습니다.

현재 지향하는 방향은 다음과 같습니다.

- **요청 전 설계 리뷰:** 무엇을 시키려는지, 빠진 조건은 없는지 함께 생각하는 것은 유효합니다.
- **설계를 꼬치꼬치 묻는 대화:** 선택의 근거와 대안을 묻는 상호작용은 핵심 경험의 후보입니다.
- **과정 중심의 개입:** 코드·diff·테스트는 대화의 근거로 활용할 수 있지만, 정적인 산출물 검토 자체를 서비스의 중심에 두지 않습니다.
- **사람의 지시 경험 유지:** 승인 여부와 무관하게 Coach가 Driver에게 직접 일을 시키는 방식은 현재 지향하지 않습니다. 무엇을 바꿀지 함께 결정하더라도 실제 작업 지시는 사람이 합니다.
- **제한적인 테스트 작성 가능성:** Coach가 테스트를 직접 코드베이스에 작성하는 방식은 보조 수단으로 검토할 수 있습니다. 구체적인 허용 범위와 승인 방식은 미정입니다.

Coach의 개입은 사람에게 생각할 거리를 주어야 하지만, 끝없이 정답을 숨기는 퀴즈가 되어서는 안 됩니다.
필요할 때 배경을 설명하고, 왜 중요한 질문인지 알려주며, 실제 작업이 진행되도록 도와야 합니다.

## 8. 핵심 가치로 삼지 않는 것

- 질문받았을 때만 개념을 설명하는 챗봇
- 코드 오류와 diff를 찾아 알려주는 기능만으로 구성된 리뷰어
- 테스트를 대신 실행해주는 편의 도구
- 사람이 할 지시문 전달을 대신 처리하는 자동화
- 사람이 모든 코드를 직접 작성하도록 강제하는 교육 도구
- 사소한 문제마다 끼어들거나 모든 결정을 대신 내려주는 가상의 시니어

이 중 일부 기능은 보조 기능으로 유용할 수 있습니다.
다만 그 기능 자체가 이번 타깃의 핵심 문제를 해결한다고 보지는 않습니다.

## 9. 이름과 연결되는 경험

**wellactually**는 “Well, actually…”로 시작해 옆에서 예외나 전제를 짚어주는 동료의 밈에서 가져온 이름입니다.

이 타깃에게 필요한 “겐세이”는 단순한 오류 지적이나 잘난 척이 아닙니다.
모르고 지나갈 뻔한 판단의 순간을 드러내고, 그 판단에 사람이 참여하도록 만드는 개입입니다.

**코드는 Driver가. 겐세이는 wellactually가. 결정과 지시는 사람이.**

## 10. 아직 검증해야 할 가설

- 비슷한 경험의 공백을 느끼는 Coding Agent Native 주니어가 얼마나 많은가?
- 특히 어떤 업무와 결정에서 공백을 크게 느끼는가?
- 선제적인 질문이 유용한 순간과 방해가 되는 순간은 어떻게 다른가?
- 사용 후 비슷한 문제에서 사람이 스스로 필요한 질문과 지시를 구성할 수 있는가?
- 체감 학습과 실제 판단 능력의 변화가 일치하는가?
- 학습에 도움이 되면서 실제 업무를 지속할 수 있는 개입 수준은 무엇인가?

“비슷한 주니어가 많을 것”이라는 예상은 출발 가설이며, 현재 확인된 시장 규모는 아닙니다.
후속 사용자 인터뷰와 실제 작업 관찰로 구체화해야 합니다.
